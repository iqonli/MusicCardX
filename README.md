## 介绍

MusicCardX是[MusicCard](https://github.com/iqonli/MusicCard)的Flutter移植版。目前先做Android，独立运行，不需要foobar2000。MusicCard里的封面、背景、阴影、文字、歌词、颜色、字间距、输出倍率和配置，X都继续做；桌面面板和Windows专用操作则换成Android上的做法。

原版说明完整保留在本文后半部分，包括历史Bug记录。Windows、foobar2000、Spider Monkey Panel和PowerShell相关内容讲的是原版，别在手机上照着装。X的入口、差异和新增功能先看下面。

## 重要提示

1. 最低Android8.0。一般手机下arm64-v8a；x86_64给对应设备和模拟器。正常更新直接覆盖安装。
2. 编辑、渲染可以离线。在线搜索才需要联网，不用登录账号，接口失效或地区没有内容时可能搜不到。
3. 配置JSON不包含封面、字体和系统目录授权。换设备时，字体和封面记得另外留一份。
4. 程序不修改音频文件Tag。搜到的版本、日期和曲序自己核对，分数高不保证一定对。
5. 同种子不保证与GDI+原版逐像素相同。Flutter的字体、模糊和取色也有差别。

## 安装与使用

从Releases下载APK。打开`输入`填歌曲信息和封面，去`工作台`改样式，在`设置`管理字体、配置和输出目录。预览满意后，分享、复制或保存。

输入框离开焦点后再刷新卡片。预览跟随输出倍率，图钉开启时固定显示，关闭后随页面滚动。预览上双指可以缩放、平移，单击看大图。分享、复制和保存按钮在顶栏。

**好看的背景要自己刷。** 这句话继承原版。X加了种子博览会，一行一张，点击用种子，长按看大图；只在融合模式显示。纯色模式可以自己指定颜色。

**为什么默认配置这么丑。** 原版怎么说，X也怎么说：图片仅供参考，请以实物为准。好看的排版自己做，配置可以保存、复制、改名，也可以导入导出JSON。

### 歌曲信息和封面

可以手填、从音频读取、编辑歌曲信息JSON，也可以接收其他APP分享进来的图片、音频、文本和JSON，替换前会确认。

`在线搜索封面`支持163、Apple和Apple不限速。预览尺寸默认150，下载尺寸默认1000，0表示向源站请求最大尺寸，返回多少看源站。低分候选可以不自动加载。

点封面看大图，右上角依次为下载、保存、✓。下载按钮取设定尺寸的大图；保存按钮存当前看到的版本，没下载就存小图；✓会先下载大图再使用，下载失败不会拿小图顶上。

**封面拿到什么就存什么，不重新压缩。** 保存时沿用文件名规则再加`-cover`。设置里的PNG／JPG和质量只影响X生成的卡片，预览不压缩。

`在线搜索歌曲信息`再加QQ音乐。标题、艺术家必填，专辑选填。结果拆成标题、艺术家、专辑、完整日期、Disc、Disc总数、Track、Track总数八行气泡流，各行单选，默认保留。八行和第一列名称一起横向滚动。

选定专辑后，日期、Disc和Track候选只取该专辑；切换专辑会把这些行恢复为保留。原值恰好是最高分候选时显示`最佳&保留`，否则第一个仍是`保留`。分数越高背景越深，分数结合原组合匹配与出现次数计算，重复记录不反复计数。选`未提供`会清空该项。右上角✓应用当前选择，底部显示各源状态和候选数量。

两个搜索页右上角的小地球可以填全球两字母区域代号，如cn、us、jp、gb，自动转小写。此项用于Apple，163和QQ没有对应的全球目录参数；不是填了代号，源站就一定有内容。

### 字体和排版

原版的系统字体枚举，在X里换成字体管理器。页面、名称解析、字体选择和字重处理都用Flutter／Dart，不依赖Kotlin字体管理器。

支持TTF、OTF、TTC、OTC和ZIP，按家族、字重分组，预览文本和字号可以自己改。可变字体有滑块、输入框和±100；普通字体选实际存在的字重。应用界面字体和生图字体分开。

`导入字体`和`依赖于ezCD`二选一。后者读取你授权目录中的ezcd-fonts.json，ezCD管字体，X只读、校验和缓存，不修改共享库。接入说明见[文档](docs/ezCD-font-sharing-v1.md)。

表格点表头改整列，点第一列改一个项目。顶部、中、底部文字对齐可在设置中切换。封面还支持独立四角、连续圆角、超椭圆、斜角、凹角等形状，各自参数分别保存。歌词排版和分隔线都保留独立开关。

### 颜色、文字和文件名

普通HEX统一小写。`black`是18、18、18，`white`是250、250、250；自动黑白可以自动判断，也可以锁黑或锁白。自定义环境色会接管背景、自动黑白和彩虹色的五个候选色。

X可以选择取色算法，也能在封面上拖动标注、连续选择五个颜色，调整取色边长和油漆桶模式。彩虹色仍用原版表达式，不透明度另算。字间距留空走整段排版，填0走逐字绘制，这个区别也保留。

卡片文字和歌词分别设置OpenCC转换。转换在标题格式化求值后进行，不改原文。X实现了常用foobar标题格式语法，尚未实现整个foobar2000引擎；未知函数会报错。原版表达式复杂时请核对结果。

文件名默认：

```text
MusicCardX-[%title%-][%artist%-][%album%-][%seed%]
```

%seed%只在融合模式有值。设置时实时预览，同名文件不直接覆盖。单张输出限制3200万像素、单边16384像素，超出会提示减小尺寸。

## 原版那些特性，X怎么处理

无封面不留占位、平铺保留比例、卡片宽度随内容变化、显示字体与生图字体分离、模糊可以做发光，这些继续保留。

X不读取播放器当前选中项，不需要休眠唤醒，也没有Windows脚本编辑菜单。切换歌曲信息不会执行原版的切歌歌词确认流程，歌词由你自己管理。

按此前移植时的约定，X的墨点使用模糊固定色块，采点使用清晰固定色块。文字渲染使用Flutter抗锯齿，不提供GDI+的六种旧渲染模式。OpenCC词典已内置，不需要另放js文件。Windows剪贴板边缘修复是原版历史，不在Flutter输出上照搬覆盖首行首列。

在线封面搜索的图片字节缓存上限80MiB，离开页面清理；这不是整个APP的内存上限。已使用封面、字体、配置和你保存的文件会保留。

## 介绍

MusicCard是一个在foobar2000 Spider Monkey Panel上运行的JavaScript脚本。程序可以读取当前曲目的封面和标签，按照用户配置生成一张推歌卡片，可以在面板中预览、复制到Windows剪贴板，或保存为图片。

卡片默认显示Title、Artist、Album和年份、Disc、Track等信息，也可以使用foobar2000标题格式化表达式自定义全部文字。封面、背景、阴影、文字、歌词、颜色、字间距、输出倍率和其他样式均可单独调整。

程序目前包含：

- 预览、复制图片、保存PNG、休眠和恢复
- `1x`、`2x`、`3x`、`4x`及`0.1x–10x`自定义导出图片倍率
- 融合、墨点、采点、模糊、纯色五种背景
- 封面裁剪或平铺、圆角、圆形裁剪和渐变阴影
- 8个可配置的卡片文字元素
- 歌词排版、对齐、裁切、光晕和三段渐变分隔线
- HEX、自动黑白和彩虹色表达式
- 从封面精确计算平均色相，或自定义彩虹目标色
- 5个可自定义的环境颜色
- 卡片文字和歌词相互独立的OpenCC简繁转换
- 配置导入、导出和配置列表选择
- 系统字体枚举及MusicCard可识别字体名检查
- 融合背景随机种子输入、复制和复现

2. MusicCard依赖于Windows版foobar2000，需要安装Spider Monkey Panel。
3. 复制图片和列出系统字体会调用Windows PowerShell、System.Drawing和Windows Forms。

## 一些~~bug~~特性！新手必看#1

### 读取哪一首曲目

MusicCard优先读取当前活动播放列表中被选中的第一首曲目；没有选中项时，再读取焦点项。因此，生成对象不一定是正在播放的曲目。切换选中项、焦点、播放列表或播放曲目，都可能触发预览刷新或关闭当前弹出预览。

### 启动后自动休眠

脚本加载或重载完成后会主动进入休眠界面。休眠会释放主页预览和样式配置预览的位图，并停止大部分持续刷新；需要点击`恢复`后才能使用主界面。这不是脚本没有加载成功。

### 好看的背景要自己刷

**融合背景模式是根据封面环境色和随机种子生成多个融合色块，所以背景好不好看全靠种子，种子要自己刷。**

### 为什么默认配置这么丑

**图片仅供参考，请以实物为准。哈哈哈哈哈哈哈哈我才不会把我的配置发出来。**

### 模糊就是发光

如果你要做字体发光，把文字的`模糊强度`改成4，`模糊不透明度`改成160-200。

### 基本使用

1. 在foobar2000中选择或播放一首曲目。
2. 点击`恢复`唤醒脚本。

## 一些~~bug~~特性！新手必看#2

### 无封面时不保留封面位置

没有读取到封面时，卡片不会显示`No Cover`图，也不会保留封面、阴影或对应空白区域，文字会向左移动，整张卡片也会变窄。程序内部仍会创建一张临时占位图，供背景调色板和彩虹色计算使用，但这张图不会作为封面绘制出来。

### “平铺”不是重复铺砖

不规则封面的`平铺`模式不会把同一张图片重复排列。它固定封面显示高度，并按照原图宽高比改变封面宽度，随后重新计算文字位置和卡片总宽度。圆角设为`180`时则进入独立的圆形模式，强制使用正方形封面并绕过普通`FillRoundRect`圆角算法。

### 卡片宽度不是固定值

同一导出倍率下，图片高度基本固定为`400 × 倍率`，宽度会根据歌词容器、分隔线、封面宽高比、标签列宽、各行文字宽度、文字光晕和水印动态计算。因此，`2x`只表示尺寸倍率，不代表固定输出为某个分辨率。

### 空字间距和0字间距完全不同

字间距留空时，MusicCard把整段文字交给字体原生排版，保留kerning、连字和字体自己的字符定位。输入任何数值时，包括`0`和负数，程序都会改为逐字绘制。`0`只表示不额外增加距离，并不等于原生排版；某些字体的连字和字偶距会因此消失。

### 显示字体和生图字体相互独立

`修改显示字体`只改变MusicCard面板前端的按钮、标题和设置界面，不改变导出图片中的Title、Artist、Album、歌词或水印字体。导出图片字体仍需在对应文字项目和歌词配置中分别修改。

### 字体名以MusicCard能识别的名称为准

Windows、字体查看器、Office、Adobe软件和foobar2000可能对同一字体显示不同名称。`列出所有字体`先通过Windows读取已安装字体族，再用Spider Monkey Panel的字体接口逐项复核，只显示MusicCard能够加载的名称。其他软件中看到的字体名不一定可以直接填入MusicCard。

### 多行编辑器可能退化为“\n”输入

正常情况下，歌词使用HTML多行编辑窗口。若当前Spider Monkey Panel环境无法打开该窗口，程序会退回普通输入框，此时需要输入字面量`\n`表示换行。

### 切歌后歌词需要人工确认

切换曲目后，MusicCard不会删除上一首已经保存的歌词，但预览会暂时显示`请输入文本`，避免把上一首歌词直接画到新曲目的卡片上。打开歌词编辑器时仍可看到原内容；只有点击保存，当前曲目才解除确认状态。取消或直接关闭编辑器不会解除。

### 所有文字先执行标题格式化，再进行OpenCC转换

Title、Artist、Album、水印和每一行歌词都可以是foobar2000标题格式化表达式。MusicCard先得到最终显示文字，再执行OpenCC简繁转换。转换只作用于画面，不修改音频标签、表达式、歌词原文、本地歌词文件或配置中的原始文字。卡片文字与歌词拥有两个独立的转换模式；旧配置中的`s2tw`会自动迁移为`s2twp`。

### `%datey%`不是foobar2000原生字段

`%datey%`是MusicCard在送入标题格式化引擎前展开的自定义写法，它只读取`%date%`的前四个字符。它不会创建或修改音频标签。

### OpenCC从三个位置依次尝试加载

程序依次尝试从以下位置读取`opencc-js-1.4.1.js`：

1. MusicCard主脚本同目录；
2. foobar2000安装根目录；
3. foobar2000的`profile`目录。

若主脚本是直接粘贴到面板编辑器中的内存脚本，“主脚本同目录”的具体解析结果取决于Spider Monkey Panel自身规则。OpenCC加载失败时，简繁模式仍会保存，但渲染保持原文。

### OpenCC转换器按需创建

即使`opencc-js-1.4.1.js`已经加载，程序也不会在启动时一次创建所有转换器。只有某个模式第一次实际使用时，才创建对应转换器并缓存，以减少默认关闭状态下的初始化开销。

### `black`和`white`不是纯黑纯白

MusicCard中的`black/#black`固定表示`RGB(18,18,18)`，`white/#white`固定表示`RGB(250,250,250)`。它们是为卡片设计保留的近黑和近白，不等于`#000000`和`#ffffff`。颜色输入留空时，则根据背景调色板自动选择近黑或近白。

### 彩虹色表达式是RGB插值，不是透明叠加

`r%n`和`r%n+颜色`会直接计算基础色与彩虹目标色之间的RGB位置。例如`r%20+#202020`表示从`#202020`向当前彩虹目标色移动20%。省略基础色时，基础色使用当前自动近黑或近白。表达式不会通过半透明图层覆盖背景，因此元素自身的不透明度仍单独计算。

### 封面取色计算的是平均色相

彩虹色的自动取色不会先平均RGB。程序先缩小封面，逐像素读取BMP，忽略没有有效饱和度的灰色像素，再使用正弦和余弦计算环形平均色相，最终生成满饱和、满亮度的目标色。主路径通过ADODB、MSXML、Base64和JavaScript解析BMP；失败时才退回调色板近似。

### 自定义环境颜色会接管多处配色

开启`自定义环境颜色`后，五个颜色不仅供界面显示，还会替代程序从封面读取的环境色，影响背景、自动黑白判断和彩虹色自定义模式中的五个候选色。关闭该功能时，五个自定义值会被清空；再次打开会从当前封面重新读取，不会恢复上一次关闭前的值。

### 融合背景的种子只对融合模式有效

融合背景使用确定性随机数。同一种子、同一封面和同一配置应得到相同背景；其他背景模式不使用种子。脚本初始化时主页预览和样式配置预览共享一次随机种子，之后分别刷新、互不联动；从样式配置弹出的预览会继承当时的设置预览种子。

### 三种彩色背景保留了不同年代的算法

`融合`、`采点`和`墨点`不是同一算法的三个参数档位：

* `融合`使用随机椭圆和可重复种子；
* `采点`沿用旧版固定四个色点，`StackBlur`半径固定为90，不随导出倍率放大；
* `墨点`故意复现v4.5实际显示出来的效果。旧版曾因读取未定义的模糊参数而让`StackBlur`报错并被空`catch`吞掉，所以现在的墨点模式有意不执行模糊。

不要在没有视觉回归对比的情况下把这三种算法“统一”或给墨点补上模糊，否则会改变已有样式。

### 模糊强度100以上通过重复模糊实现

Spider Monkey Panel的`StackBlur`单次半径存在上限。MusicCard让`0–100`保持旧版效果，`100–500`通过追加多轮模糊继续增强，因此500不是简单把同一半径参数改大。

### 图片第一行和第一列有历史兼容修复

MusicCard曾长期出现Windows剪贴板把顶部第一行和左侧第一列显示为近白、透明或黑色的问题。v4.16.7在最终`gdi.Image`生成后，用第二行覆盖第一行、第二列覆盖第一列，并用`(1,1)`像素修正左上角。对应函数是`replaceTopLeftEdgePixels()`。这段处理同时进入预览、保存和复制使用的最终位图，不能只因为保存PNG看起来正常就随意删除。

### 复制图片会经过临时PNG和24bpp RGB

复制图片不是直接把`gdi.Image`交给剪贴板。程序先在输出目录写入并覆盖固定临时文件`__music_card_clipboard_v4167.png`，再启动PowerShell，通过System.Drawing把它烘焙为白底24bpp RGB位图，最后调用Windows Forms写入剪贴板。当前实现不会在复制完成后删除该临时PNG。

### 保存重名图片不会覆盖旧文件

默认文件名为`标题-艺术家.png`。若文件已经存在，程序会依次生成`标题-艺术家 (1).png`、`标题-艺术家 (2).png`，而不是覆盖原文件。

### 配置属性名不会随程序版本全部改名

部分Spider Monkey Panel属性键仍包含`v4.13.1`、`v4.15`或`v4.16`等旧版本号，这是为了继续读取既有用户设置，不代表对应功能仍停留在旧版本。发布新版本时不要机械地把所有属性键改成当前版本号。

### 配置导入会主动迁移历史状态

配置文件带有独立的schema版本。导入旧配置时，程序会修正历代Album第二行表达式，把旧的特殊字间距`-1`迁移为空值，并把`s2tw`迁移为`s2twp`。配置读取还会尝试UTF-8和UTF-16文本。维护配置系统时应继续新增迁移步骤，而不是直接覆盖旧逻辑。

### 取消输入和输入空值必须区分

MusicCard中很多空值本身具有意义，例如空字间距、自动颜色和随机种子。程序通过专门的取消哨兵区分“点击取消”和“确认空字符串”。不要把取消重新改成普通空字符串判断，否则会让Cancel继续执行，或使合法空值无法保存。

### 背景模式

MusicCard提供五种背景：

| 模式 | 说明 |
| --- | --- |
| 融合 | 根据封面环境色和随机种子生成多个融合色块 |

- 模糊强度`0–500`
- 背景截取封面位置`0–100%`

1. 用户自定义封面
2. 当前曲目的内嵌封面
3. foobar2000提供的专辑封面
4. 无封面

非正方形封面支持：

- `裁剪`：按卡片封面区域裁剪为1:1；
- `平铺`：保持封面高度，宽度按原始比例变化，并推动右侧文字。

封面圆角范围为`0–180`，输入`180`时直接裁为圆形。

封面阴影支持独立设置不透明度和深度；不透明度为`0`时关闭阴影。

Album 文本第二行

每个元素可以单独设置：

- 字体
- 粗体
- 斜体

- 模糊强度
- 模糊不透明度

### 字间距

字间距单位为px，支持正数、负数和最多三位小数。

```text
留空：使用字体原生整段排版，保留kerning和连字

正数：逐字绘制并增加间距
负数：逐字绘制并压缩间距
```

留空和`0`为两个不同状态，其中`0`是逐字绘制，会失去字体原生连字。

MusicCard支持`SetTextRenderingHint()`的`0–5`：

```text
0 SystemDefault
1 SingleBitPerPixelGridFit
2 SingleBitPerPixel
3 AntiAliasGridFit
4 AntiAlias
5 ClearTypeGridFit
```

默认使用`3`。

### 显示字体和导出字体

`修改显示字体`只影响MusicCard面板中显示文字。

`列出所有字体`会：

1. 使用`System.Drawing.Text.InstalledFontCollection`读取系统字体族；
2. 过滤以`@`开头的竖排字体名；
3. 使用`utils.CheckFont`或`gdi.Font`逐项复核；
4. 只列出MusicCard能够识别的准确字体名。

字体列表支持筛选、选择、双击和复制名称。部分字体在不同软件中使用的名称不同，给MusicCard填写字体时，应优先使用这里列出的名称。

面板默认显示字体为`微软雅黑`。

### 普通HEX和自动黑白

普通颜色支持六位HEX，可省略`#`：

```text
#abcdef
abcdef
```

输入内容会统一格式化为小写。

自动黑色支持：

```text

BLACK
```

实际颜色为：

```text

```

自动白色支持：

```text
white
#white
WHITE
```

实际颜色为：

```text
RGB(250,250,250)
```

颜色留空时，程序会根据背景自动选择黑色或白色。

### 彩虹色目标色

彩虹色目标色支持两种来源：

- `自动取色`：缩小封面后，逐像素计算平均色相；
- `自定义`：使用固定HEX、自动黑白或封面的5个风格色之一。

取色模式会忽略无饱和度像素，对每个有效像素的Hue进行环形平均，再用完整饱和度和亮度生成目标色。

`取色封面边长`范围为`1–1000`，默认`150`。数值越大，结果越接近完整封面，但会增加计算时间。

### 彩虹色表达式

通过将基础色和目标色进行一定比例的混合，可以将文字更好地融入背景。

标准彩虹色表达式：

```
rainbow%n+hex
```

其中`rainbow%`是固定字段，也可以写作`r%`；`n`表示颜色截取位置，范围为`0–100`，最多三位小数；`+hex`是选填项，表示基础色，其中`hex`是普通HEX表达式，如果不填写此项，基础色将使用当前自动黑色或自动白色。

计算方法：`n% × #hex + (100 - n)% × 目标色`

整段表达式的意思是：从基础色`hex`出发，到目标色这一条色带上，截取`n`位置的颜色，即为这个表达式的颜色。

彩虹色表达式支持：

```text
rainbow%n
rainbow%n+hex
r%n
r%n+hex
```

例如：

```
rainbow%20
rainbow%20+#114514
r%20
r%20+114514
```

## OpenCC简繁转换

MusicCard使用本地`opencc-js v1.4.1`。卡片文字和歌词有两个独立按钮，均按以下顺序循环：

1. `关闭`：原文；
2. `t2s`：繁体转简体；
3. `s2t`：简体转传统汉字；
4. `s2twp`：简体转台湾繁体及常用词；
5. `s2hk`：简体转香港繁体。

卡片文字按钮控制Title至水印的8个文字元素；歌词按钮只控制歌词。

转换发生在标题格式化表达式求值之后，只改变最终显示文字。

OpenCC加载失败时，程序会显示尝试位置、实际路径、失败原因和下载地址。简繁模式仍会保存，但渲染保持原文。

官方npm归档：

```text
https://registry.npmjs.org/opencc-js/-/opencc-js-1.4.1.tgz
```

归档中的完整UMD文件：

```text
package/dist/umd/full.js
```

将它重命名为：

```text
opencc-js-1.4.1.js
```

## 历史遗留Bug记录

> 以后修改README时请勿移除本节。

### 问题

MusicCard长期存在一个Windows剪贴板边缘兼容问题。生成的图片通过不同剪贴板像素格式复制后，顶部第一行和左侧第一列可能显示为非纯白、透明或黑色。直接保存PNG通常正常，因此该问题曾被误判为背景、封面或PNG最外缘插值问题。

### 诊断结果

测试过的剪贴板路径表现为：

| 路径 | 结果 | 实际含义 |
| --- | --- | --- |
| 24bpp RGB、白底 | 非纯白 | 异常边缘的Alpha被压平到白色背景 |
| 32bpp PArgb | 透明 | 异常边缘的Alpha被保留 |
| 直接BMP | 黑色 | Alpha丢失后，隐藏RGB被解释为黑色 |
| WPF BitmapSource | 透明 | WPF保留了PNG中的透明边缘 |
| 24bpp DataObject、白底 | 非纯白 | 更换剪贴板提交方式没有改变问题本质 |

`Clipboard.SetImage()`和`Clipboard.SetDataObject()`得到相同类型的结果，说明剪贴板API并不是唯一问题来源。不同路径只是在用不同方式显示同一组最终位图边缘异常像素。

### 已验证修复

v4.16.7保留了T1方案：

1. `buildCard()`完成最终`gdi.Image`绘制；
2. 以`1:1`方式复制整张图片；
3. 用第2行覆盖顶部第1行；
4. 用第2列覆盖左侧第1列；
5. 左上角使用坐标`(1,1)`的像素；
6. 其余像素不缩放、不插值；
7. 随后使用24bpp RGB路径复制到Windows剪贴板。

对应函数：

```text
replaceTopLeftEdgePixels()
```

## 常见问题

### 点击简繁转换后文字没有变化

检查`opencc-js-1.4.1.js`是否位于MusicCard主脚本同目录或foobar2000配置目录根部，然后重载脚本。程序的错误弹窗会列出每次加载尝试的路径和失败原因。

### 输入字体名后仍显示为其他字体

不同软件可能展示字体的显示名、家族名或本地化名称。点击`列出所有字体`，复制MusicCard复核通过的准确字体族名，再填入卡片文字或歌词字体。

### 修改显示字体后，导出图片没有变化

这是正常行为。`修改显示字体`只修改MusicCard面板前端；导出图片字体需要在8个文字元素或歌词设置中修改。

### 字间距输入0后，字形和留空时不同

这是正常行为。留空使用字体原生整段排版；输入`0`会切换到逐字绘制，因此可能失去连字和部分kerning。

### 没有封面时为什么卡片变窄

无封面状态不会保留封面占位。MusicCard会重新计算动态宽度，使文字从左侧开始排版。

### 复制图片失败

复制图片依赖Windows PowerShell、System.Drawing和Windows Forms。检查PowerShell能否正常启动、执行策略是否阻止脚本，以及安全软件是否拦截临时PNG或剪贴板访问。

### 预览和复制得到的融合背景不同

确认两次生成使用了相同种子。可以在预览中复制种子，再通过`Input`输入同一内容。
